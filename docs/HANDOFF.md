# Передача проекта: что готово, что осталось, куда смотреть

Коротко: это Telegram-бот «Эпидемик» — копия игры «Эпидемик 2.0» (@epidemic2_bot) для групповых чатов,
плюс админ-панель для владельца. Ядро игры написано, проверено тестами (195 штук) и вживую на тестовом боте.
На сервер клиента бот **ещё не выкладывался**. Сделать это и довести до сдачи — твоя задача.

---

## 1. Главное правило проекта

Клиенту нужен бот **1 в 1 как оригинал**: те же тексты, эмодзи, переносы строк, формат чисел, кнопки.
Даже опечатки оригинала («Ты все таки», «Улучшение на 1 уровней», «Приветсвия») оставлены специально.

- Не «исправляй» тексты игроков, даже если режут глаз.
- Все места, где мы **сознательно** отступили от оригинала, перечислены в `docs/REFERENCE_SPEC.md`, раздел 4.
  Если делаешь новое отличие, допиши его туда же.
- Эталон — скриншоты оригинала от клиента. Они лежат у меня (папка `REFTGBOT`), попроси их: без них
  сверять внешний вид не с чем.

## 2. Как запустить за 5 минут

```bash
python -m venv .venv && .venv\Scripts\activate      # Linux/Mac: source .venv/bin/activate
pip install -r requirements-dev.txt
copy .env.example .env                              # впиши BOT_TOKEN (тестового бота!) и ADMIN_ID
python -m epidemic                                  # бот запущен
pytest                                              # все тесты, ~5 секунд
```

- Для проверки заведи **своего тестового бота** в @BotFather и выключи ему privacy mode
  (`/setprivacy` → Disable), иначе в группе он не увидит «лаб», «заразить» и т. д.
- Папка `.pydeps/` — костыль с моего компьютера (там не создавался venv). Тебе она не нужна, удали.
- Папка `data/` — моя тестовая база, тоже можно удалить: при запуске создастся новая.

## 3. Что осталось сделать (по порядку)

### Обязательно до сдачи

1. **Первый деплой на сервер клиента.** Инструкция для клиента — `README.md`, раздел 2. Архив для него
   собирается командой `python -m tools.build_archive` → `dist/epidemic-bot.tar.gz`.
   Важно: Docker-образ **ещё ни разу не собирался** (на моём компьютере нет Docker). Первый
   `docker compose up -d --build` проверь сам или вместе с клиентом и посмотри `docker compose logs`.
2. **Узнать у клиента и вписать в его `.env`:** ссылки `GUIDE_URL`, `CHAT_URL`, `CHANNEL_URL`,
   `RULES_URL` и контакты поддержки `SUPPORT`. Пока они пустые, меню `/start` выглядит пустовато.
3. **Картинки обучения.** В `media/` сейчас временные заглушки (чашка Петри). Арт оригинала брать
   нельзя — авторские права. Попроси у клиента свои картинки и положи с теми же именами (`media/README.md`).
4. **Старый бот клиента.** Узнай, работает ли его прошлый бот (`bot.py`) на том же токене. Если да —
   остановить до запуска нашего, иначе два бота будут мешать друг другу. Если клиент хочет сохранить
   игроков — перенос: `README.md`, раздел 4. Инструмент переноса проверен только на искусственной
   базе со схемой старого бота: **сначала прогони его на копии настоящей базы**.
5. **Живая проверка в группе с 2–3 аккаунтами** (тесты это покрывают, но глазами тоже надо):
   заражение друг друга, горячка и вакцина, КД, корпорации (создать → вступить по коду → принять →
   кик), «мф», «мж топ», прощание с вышедшим участником (бот должен быть админом группы),
   админ-панель `/admin`, «эпиас»/«эпимут», ежедневная премия в 00:00 и 12:00.
6. **Сверка со скринами** клиента по `docs/REFERENCE_SPEC.md` — каждый экран отмечен там отдельно.

### Не сделано специально — спросить клиента, нужно ли

В оригинале есть ещё системы, которых нет на скринах и которые не входят в ядро «биовойн»: питомцы,
кейсы, донат, казино, банк, босс, браки, ивенты, рефералы, «эпилав», перенос лаборатории «эпилаб».
Каждая — отдельная большая фича. Если клиент захочет, сначала опиши механику (что делает, какие числа),
согласуй с ним и только потом пиши код.

### Известные мелочи (не срочно)

- **Сеть в РФ.** Провайдеры иногда режут доступ к Telegram: бот получает сообщения с задержкой, первый
  запрос при старте может зависнуть. Бот сам переподключается (таймаут 20 с, повтор при старте). Если на
  сервере клиента связи с Telegram нет совсем, понадобится прокси — его пока нет.
- **Антифлуд**: сообщения чаще раза в 0,3 с от одного игрока бот молча пропускает. Это нормально.
- Финальный текст обучения написан нами в стиле оригинала: в оригинале финал был сломан.

## 4. Где что лежит

| Что нужно поменять | Куда смотреть |
|---|---|
| Команду (как бот её понимает и что отвечает) | `epidemic/handlers/` — один файл на раздел: `lab.py`, `infect.py`, `corp.py`, `chat.py`, `mass.py` («мф»), `admin/` |
| Текст сообщения | `epidemic/views/*.py` и `epidemic/texts.py`; обучение — `epidemic/data/story.yml`; РП, заметки, правила — `epidemic/data/chat.yml` |
| Кнопки | `epidemic/keyboards.py` |
| Правила игры, формулы, числа | `epidemic/game/` (`formulas.py`, `constants.py`, `infection.py`, `upgrade.py`, `corps.py`) |
| Запросы к базе | `epidemic/repo/` |
| Таблицы базы | `epidemic/schema.py` (миграции) |
| Фоновые задачи: производство патогенов, премия, бэкапы | `epidemic/services/scheduler.py` |
| Настройки из `.env` | `epidemic/config.py` |

Документация:

- `CLAUDE.md` — самое сжатое описание устройства проекта и правил (читать первым).
- `docs/ARCHITECTURE.md` — схема базы, формулы, как устроено заражение.
- `docs/REFERENCE_SPEC.md` — сверка со скринами и список отличий от оригинала.
- `README.md` — для клиента: установка, настройки, обслуживание, перенос старой базы.
- `.claude/skills/epidemic-bot/SKILL.md` — как вносить изменения, чтобы ничего не сломать.

## 5. Куда лучше не лезть (или очень аккуратно)

- **Числа и формулы** в `game/constants.py` и `game/formulas.py` взяты из оригинала. Меняй только если
  клиент прямо попросил. Для настройки баланса на ходу есть `/set_game_setting` в админке.
- **Старые миграции** в `schema.py` после первого деплоя не редактировать — только добавлять новую
  в конец списка. До первого деплоя миграцию 3 ещё можно править.
- **Внутри `async with db.tx()` не отправлять сообщения в Telegram**: пока идёт отправка, все остальные
  игроки ждут, бот «лагает».
- **Фильтры команд** писать через `cmd(...)` из `handlers/common.py`, а не через `F.text.regexp(...)`:
  второй вариант заметно тормозит в больших группах.
- **Действия админов** — изменение и запись в журнал `admin_log` в одной транзакции, и проверка
  `outranks()`, чтобы младший админ не мог наказать старшего или отменить его наказание.
- **`docker compose down -v`** на сервере удаляет базу вместе с игроками. Без `-v` — безопасно.
- **Исходник оригинального бота на GitHub** содержит чужие утёкшие токены, сессии аккаунтов и дампы
  баз. Код смотреть можно, **файлы `input`, `*.session`, `*.sql`, `victims*` не открывать и не использовать**.
- **`.env` не коммитить и не отправлять**: там токен бота.

## 6. Как проверить, что ничего не сломал

- `pytest` — 195 тестов. Самые полезные:
  - `tests/test_reference_texts.py` — тексты экранов посимвольно, как на скринах;
  - `tests/test_bot_flow.py` и `tests/test_original_systems.py` — сценарии «игрок пишет → бот отвечает»
    через настоящий диспетчер с фейковым Telegram (`tests/harness.py`).
- Поменял текст — прогони тесты: если он был сверен со скрином, тест покажет, что изменилось.
- После изменений пересобери архив для клиента: `python -m tools.build_archive`.
