# Эпидемик — архитектура

Текстовая Telegram-игра «био-войны» для групповых чатов. Клон ядра «Эпидемик 2.0»
(лаборатория, прокачка, заражения, горячка, премия, биотопы, корпорации, обучение)
плюс админ-панель клиента из исходного `bot.py`.

## 1. Принятые решения

| Вопрос | Решение |
|---|---|
| Объём | Ядро био-войн 1:1 + админка клиента. Питомцы, донат, казино, браки — вне этого этапа |
| Стек | Python 3.12, aiogram 3, SQLite (aiosqlite, WAL), без Redis |
| Деплой | Docker Compose, один сервис, база в volume `./data` |
| Часовой пояс | `Europe/Moscow` по умолчанию (переменная `TZ` в `.env`) |
| Брендинг | Название игры, ссылки на гайд/чат/канал, поддержка — через `.env` |
| Картинки | `media/tutorial_begin.jpg`, `media/tutorial_end.jpg` — кладёт клиент; без них шлётся текст |
| Старые игроки | Скрипт `tools/migrate_from_biowars.py` переносит базу старого `bot.py` |
| Команды | Текстовые, как в оригинале (`лаб`, `заразить`, `++зз`); кнопки — где они были в оригинале |

## 2. Компоненты

```
Telegram ─► aiogram Dispatcher
             │  outer middleware: Registration (user + lab + участник чата)
             │  inner middleware: Access (техработы, игнор), Throttling
             ▼
           Routers: admin → start → upgrade → lab → infect → biotop → corp → misc
             │
             ▼
           game/*  — чистые формулы и игровые сервисы (infection, upgrade, economy)
             │
             ▼
           repo/*  — SQL-запросы по доменам
             │
             ▼
           Database — одно соединение aiosqlite, asyncio.Lock на запись, транзакции
             │
             ▼
           data/epidemic.sqlite3  (Docker volume)

Фоновые задачи (services/scheduler.py):
  • производство патогенов — тик каждые 15 с, с догоном пропущенных интервалов
  • ежедневная премия — слоты 00:00 и 12:00 (TZ), идемпотентно, с догоном 1 пропущенного слота
```

## 3. Схема БД

Все времена — unix-секунды (UTC). Часовой пояс нужен только для слотов премии и дат в тексте.

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| `users` | все, кто писал боту или в чат с ботом | `user_id` PK, `full_name`, `username` (уник., NOCASE), `tutorial_done` |
| `labs` | лаборатория игрока | навыки `pathogens`, `ready_pathogens`, `science`, `infect`, `immunity`, `lethality`, `security`; `bio_exp`, `bio_res`; `science_time` (следующий патоген); `fever_until`, `fever_pathogen`; `notify_chat_id`; `dossier_open`; `hidden`; `disabled*`; `lab_name`/`lab_key`, `pathogen_name`/`pathogen_key` (уник. ключи в casefold) |
| `victims` | активные заражения | PK (`owner_id`, `victim_id`), `expires_at`, `cooldown_until`, `earn`, `pathogen_name`, `ss_detect` |
| `corporations` | корпорации | `corp_id`, `code` (6 симв.), `name`/`name_key`, `leader_id` (уник.), `dossier_open` |
| `corp_members` | участники | `user_id` PK, `corp_id`, `role` leader/admin/member |
| `corp_requests` | заявки | PK (`corp_id`, `user_id`) |
| `chat_members` | кто есть в каком чате (для `бч`) | PK (`chat_id`, `user_id`) |
| `chats` | чаты с ботом (группы и ЛС) | `chat_id`, `title`, `is_private`, `greet_join`, `greet_leave`, `rules` |
| `chat_notes` | заметки беседы | PK (`chat_id`, `note_id`), `title`/`title_key` (уник. в беседе), `text` (HTML) |
| `infection_log` | успешные заражения (статистика) | `attacker_id`, `victim_id`, `created_at` |
| `settings` | глобальные настройки и служебные значения | `key`, `value` |
| `admins`, `admin_log`, `sanctions`, `banned_names` | админка клиента | виды санкций: `warning`, `ignore` («+ас»), `game_mute` («эпиас»), `lab_disabled`, `name_mute` («эпимут») |

Уникальность названий проверяется по `*_key = casefold(name)`: встроенный NOCASE в SQLite
не приводит кириллицу к одному регистру.

## 4. Игровые формулы (из оригинала)

| Механика | Формула |
|---|---|
| Старт | 15 000 🧬, 1 000 ☣️, патогены 4/4, навыки 1 |
| Цена прокачки | `Σ (i+1)^k` для i от текущего до целевого−1, × `upgrade_cost_multiplier_pct` |
| Показатели k | патоген 2.0, разработка 2.5, заразность 2.55, иммунитет 2.5, летальность 1.95, безопасность 2.1 |
| Лимиты | разработка ≤ 60; за раз ≤ 50 уровней; понижение возвращает 50 % (не выше базовой цены) |
| Производство | 1 патоген за `(61 − разработка)` мин ÷ `production_speed_multiplier_pct` |
| Шанс | разница `зз − иммунитет` ≥ 0 → 100 %, иначе таблица (−1 75 %, −5 15 %, −10 6 %, −50 1 %, −100 0.1 %, −200 0.001 %) |
| Патогены на атаку | 1–10; шанс × `1 + (N−1)·0.2722` |
| Повтор за 60 с | к накопленному шансу добавляется `база / 4 × множитель` |
| Запрет | разница > `max_infection_gap` (221) |
| Награда | `10 % опыта жертвы`, при иммунитете выше: `/ (1 + разница/100)`, ≥ 1, × `xp_multiplier_pct`; жертва теряет базовую сумму |
| Горячка жертве | `max(1, летальность_атакующего // 3)` мин × `fever_multiplier_pct`, накопление ≤ 60 мин |
| Срок жертвы | летальность атакующего, в днях |
| КД на пару | `infection_cooldown_minutes` (120) |
| Вакцина | `иммунитет × 15` 🧬, только при горячке |
| Случайная цель | `+` опыт выше, `=` от ÷1.5 до ×1.5, `-` ниже (без уведомления жертве); без КД, скрытых, отключённых и непробиваемых |
| Премия | в 00:00 и 12:00 — сумма `earn` активных жертв × `daily_reward_multiplier_pct`; записи удаляются, когда истекли и срок, и КД |
| СБ | СБ жертвы > СБ атакующего → жертва видит, кто заразил |

## 5. Поток заражения

```
заразить <цель|режим> [N]
  → разбор команды (цель: reply / @username / t.me / tg:// / ID / text_mention;
                    режим: + = - рандом; N ≤ 10)
  → проверки: бот? есть лаба? сам себя? отключена? горячка? КД? патогены? разница?
  → бросок с накоплением шанса
  → провал: −N патогенов, «Шкала пробития», уведомление жертве при СБ и N ≥ 2
  → успех (одна транзакция):
       атакующий +опыт, −патогены, таймер производства
       жертва −опыт, горячка
       victims upsert (срок, КД, earn)
  → ответ в чат + уведомление жертве в её чат «+вирусы» (по умолчанию — ЛС)
```

## 6. Конкурентность и нагрузка

- Одно соединение aiosqlite. Все записи идут через `Database.tx()` под `asyncio.Lock`,
  поэтому транзакции не перемешиваются. Вложенная транзакция — ошибка (защита от взаимной блокировки).
- Проверки и изменения делаются внутри одной транзакции (read-modify-write) в сервисах `game/`.
  Сетевые запросы к Telegram — только после выхода из транзакции.
- Повторные клики и спам: троттлинг 0.3 с на сообщения и 0.5 с на кнопки.
- Через фильтры проходит каждое сообщение группы, поэтому все фильтры команд асинхронные
  (`handlers/common.Cmd`): синхронные фильтры aiogram выполняет в отдельном потоке.
- Регистрация игроков кэшируется (LRU) — запись в БД только при новом игроке или смене имени.
- Тик производства читает только наступившие таймеры (частичные индексы `idx_labs_timer`,
  `idx_labs_idle`); списки жертв и счётчики идут по покрывающим индексам.
- Бэкап делается отдельным соединением и не блокирует игру.

## 7. Безопасность

- Только параметризованный SQL; имена колонок — из белых списков.
- Callback-данные строго типизированы (`Literal`, ограниченные числа): подделанная или устаревшая
  кнопка не проходит фильтр. Личные кнопки привязаны к владельцу.
- Все пользовательские строки экранируются; названия — ограниченный набор символов.
  Длинные списки собираются через `join_limited`, чтобы не превышать лимит Telegram и не резать HTML.
- Роли: владелец (`ADMIN_ID`) > старший админ > админ; экономические команды — от старшего.
  Наказать можно только того, кто ниже по должности. Суммы и уровни в админ-командах ограничены.
- Все действия админов пишутся в `admin_log` в одной транзакции с самим изменением.
- Возврат при понижении навыка не превышает базовой цены — повышение множителя цены не создаёт
  способа «печатать» ресурсы.

## 8. Деплой

`Dockerfile` (python:3.12-slim) + `docker-compose.yml` (один сервис `bot`, `restart: unless-stopped`,
volume `./data`, `./media`, ротация логов). Настройка — `.env`. Бэкап — `sqlite3 .backup`
через `docker compose exec`. В @BotFather нужно выключить privacy mode, иначе бот не видит
текстовые команды в группах.
